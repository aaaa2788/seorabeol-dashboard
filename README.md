# 서라벌 블로그 성과판

**발행한 블로그 글마다 "발행 전 순위 → 발행 뒤 순위"를 한 줄로 놓고, 오른 글과 빠진 글을 한눈에 보는 화면입니다.**

서라벌한의원 원장이 PC로, 다음 글을 뭘 쓸지 정하기 전에 봅니다.

## 왜 만들었나

기존 현황판은 "앞으로 뭘 쓸까"만 보여줬습니다. 순위가 바뀌면 옛 순위가 덮어써져 사라져서, **"쓴 글이 효과가 있었나"는 볼 수 없었습니다.**
이 성과판은 순위를 날짜별로 쌓아 둡니다(Supabase). 그래서 발행 전후를 비교할 수 있습니다.

## 화면

- 맨 위 네 칸 — 순위 올라감 / 내려감·빠짐 / 그대로 / 아직 안 잼. **누르면 아래 목록이 그 조건으로 걸러집니다.**
- **내려감·빠짐**에는 발행 뒤 올랐다가 도로 내려온 글도 들어갑니다. 전과 비교하면 "그대로"지만, 가장 먼저 다시 봐야 할 글이기 때문입니다.
- 발행 당일에 잰 순위는 전후를 알 수 없어 뺍니다.
- 순위가 오른 것이 꼭 그 글 덕분이라고 단정하지 않습니다. "발행 뒤 이렇게 됐다"는 기록입니다.

## 구조

```
public/            화면 (Vercel이 이 폴더를 올린다)
  index.html · app.js
  sample.js        로그인 전에 보이는 예시 데이터 (지어낸 값)
scripts/
  import.js        서라벌 CSV → 검사 → Supabase
  build-config.js  Vercel 환경변수 → public/config.js (키를 저장소에 안 적기 위해)
supabase/
  schema.sql       표와 보안 규칙
```

### Supabase 표

| 표 | 무엇 | 왜 이렇게 나눴나 |
|---|---|---|
| `seo_posts` | 발행한 글 (발행일·키워드·계정·제목·링크) | 글 하나에 순위 기록이 여러 번 붙으므로 따로 둔다 |
| `seo_rank_snapshots` | 키워드 × 잰 날짜마다 계정별 순위 한 줄 | **덮어쓰지 않고 쌓는 것**이 핵심. 빈칸 = 그날 노출 없음 |
| `seo_viewers` | 볼 수 있는 이메일 | 이메일 링크 로그인은 누구나 할 수 있어서, 여기 적힌 사람만 읽게 한다 |

- 화면(브라우저)은 **읽기만** 합니다. 넣는 것은 PC의 `import.js`가 비밀 키로만 합니다.
- **넣기 전에 검사합니다.** 순위가 1~100 숫자가 아니거나 날짜 형식이 이상하면 **하나도 넣지 않고 멈춥니다.**
- 실제 키워드·순위는 저장소에 없습니다. Supabase에만 있고, 로그인한 사람만 봅니다.

## 쓰는 법

```bash
node scripts/import.js --미리보기   # 검사만
node scripts/import.js --로컬       # 내 PC에서만 실제 데이터로 보기 (public/local-data.js, 안 올라감)
node scripts/import.js              # Supabase에 넣기
```

키는 서라벌한의원 폴더의 `_원본/키/.env`에 둡니다 (저장소 밖).

```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SECRET_KEY=...
```

Vercel 환경변수에는 화면용 키만 넣습니다: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`.
